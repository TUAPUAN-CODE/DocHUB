# Quality Highlight — Note การผลิต (แทนไฟล์ Excel QUALITY HIGHLIGHT)

## สิ่งที่มีให้ (ข้อมูล REV.9 ใส่ให้เองตอนเปิดระบบ)

```
Quality Highlight Report/                 (โฟลเดอร์ — มีอยู่แล้วใช้ต่อ ไม่สร้างซ้ำ)
└── Data/                                 (โฟลเดอร์ย่อย — มีอยู่แล้วใช้ต่อ)
    └── Quality Highlight - Master        (ไฟล์ · ชีต Master 396 แถว + รูป 3 รูป · Rev.9 · แดชบอร์ด "Quality Highlight")
```

| คอลัมน์ในชีต Master | ชนิด | หมายเหตุ |
|---|---|---|
| Sub Doc No. | ข้อความ (บังคับ) | หนึ่ง Sub Doc No. มีได้หลายแถว (หลาย Short Code) |
| Material | ข้อความ | |
| Short Code | ข้อความ | |
| ให้Spread | ข้อความยาว | Note ที่ต้องแจ้ง / ควบคุม |
| รูปภาพ | รูปภาพ | ใส่ได้หลายรูปต่อแถว (ถ่ายจากมือถือหรือเลือกไฟล์) — แสดงในแดชบอร์ด |
| วันที่ Update ข้อมูล | วันที่ | **ระบบเติมให้เอง** ทุกครั้งที่เพิ่ม/แก้แถว (ค่าจาก Excel คงไว้) |
| Updated by | ข้อความ | **ระบบเติมชื่อผู้แก้ไขให้เอง** (ค่าจาก Excel คงไว้) |
| วันที่ Update (ข้อความเดิมใน Excel) | ข้อความยาว | เฉพาะแถวที่ Excel เขียนหลายวันในช่องเดียว เช่น `2/11/2022 2.20/01/2024` (ช่องวันที่ใช้วันล่าสุด) |

แดชบอร์ด **Quality Highlight**: ช่องค้นหา Sub Doc No. / Short Code → แสดงทุกแถวที่ตรง (Sub Doc No. เดียวกันรวมเป็นการ์ดเดียว) พร้อม Material, Short Code, ให้Spread, วันที่/ผู้แก้ และรูป · ด้านขวาแสดง **Rev ล่าสุด และสิ่งที่เปลี่ยน** จาก Rev ก่อนหน้า · บนมือถือวิดเจ็ตเรียงลงมาทีละชิ้นเต็มความกว้าง

### Rev ใหม่จาก Excel (REV.10, …)

ปกติแก้ใน DocHUB แล้วกด **ออก Rev** (ข้างล่าง) ไม่ต้องกลับไปใช้ Excel · ถ้าจำเป็นต้องนำเข้า Excel ทั้งไฟล์อีกครั้ง ใช้สคริปต์นำเข้า
(อ่านไฟล์บนเครื่องที่รัน ผ่าน API ปกติ — ตรวจสิทธิ์ / บันทึกประวัติเหมือนกรอกผ่านหน้าเว็บ):

```
cd server
set DOCHUB_URL=http://localhost:4000/api
set DOCHUB_USER=<บัญชี master หรือ admin>
set DOCHUB_PASSWORD=<รหัสผ่าน>
npx ts-node --transpile-only scripts/seedQualityHighlight.ts --file "D:\QC\REV.10_QUALITY_HIGHLIGHT.xlsx" --folder "Quality Highlight Report" --sub "Data" --name "Quality Highlight - Master" --dashboard "Quality Highlight" --dry
```

- `--dry` แสดงว่าจะนำเข้าอะไร (จำนวนแถว รูป วันที่ที่เป็นข้อความ คำเตือน) โดยยังไม่สร้าง — เอา `--dry` ออกเพื่อนำเข้าจริง
- Rev แรกใช้เลขหลัง `REV.` ในชื่อไฟล์ (REV.10 → Rev.10) หรือกำหนดเองด้วย `--rev 10`
- สคริปต์หยุดถ้ามีไฟล์ชื่อเดียวกันอยู่แล้ว (ไม่เขียนทับ) → ใช้ `--name` ชื่ออื่น หรือย้ายไฟล์เดิมลงถังขยะก่อน
- ให้ข้อมูลชุดใหม่ใส่เองตอนเปิดระบบแบบ REV.9 (สำหรับนักพัฒนา): นำเข้าในเครื่องทดสอบ แล้ว
  `npx ts-node --transpile-only scripts/exportSeedSql.ts --file-id <id ของไฟล์> --out ../database/seed/<ชื่อใหม่>.sql` → build + commit
  (ชื่อไฟล์ seed ใหม่ = ทำอีกครั้งในทุกฐานข้อมูล; repo เป็น public — ข้อมูลที่ใส่ใน `database/seed` ทุกคนเห็นได้)

## การใช้งาน

**ดูข้อมูล (พนักงาน):** เปิดแดชบอร์ด Quality Highlight → พิมพ์ Sub Doc No. หรือ Short Code (พิมพ์บางส่วนได้) → แตะรูปเพื่อดูเต็มจอ, "ดูทั้งหมด" เพื่ออ่าน Note ยาว

**แก้ไข Master (ผู้ดูแล):**
1. เปิดไฟล์ Quality Highlight - Master → แก้ / เพิ่มแถว / ใส่รูปในคอลัมน์ "รูปภาพ" (เพิ่มได้หลายรูป)
   วันที่ Update และ Updated by เปลี่ยนให้เอง
2. ปุ่ม **Rev.N** บนแถบเครื่องมือจะมีตัวเลข `+จำนวนแถว` ที่แก้ไปแล้วแต่ยังไม่ออก Rev
3. กดปุ่ม → ดูรายการเปลี่ยนแปลง (แก้ไข: ค่าเดิมขีดฆ่าสีแดง → ค่าใหม่สีเขียว · เพิ่มใหม่ · ลบออก) → ใส่หมายเหตุ → **ออก Rev.N+1**
4. แดชบอร์ดแสดง Rev ใหม่ทันที และติดป้าย "แก้ไขใน Rev.N" / "ใหม่ใน Rev.N" ที่แถวที่เปลี่ยน
5. ดู Rev เก่า: เมนู ⋯ ของไฟล์ → "Rev ของชีตนี้" หรือเลือกจาก dropdown ในวิดเจ็ต Rev ของแดชบอร์ด

สิทธิ์: ดูแดชบอร์ด = อ่านไฟล์ได้ · แก้ข้อมูลและออก Rev = เขียนไฟล์ได้ · แก้หน้าแดชบอร์ด = จัดการไฟล์ได้ (แชร์ที่โฟลเดอร์ Quality Highlight Report)

## ฟีเจอร์ที่ใช้กับไฟล์อื่นได้ด้วย

- **ออก Rev** ทุกชีต: เมนู ⋯ ของไฟล์ → "ออก Rev / ประวัติ Rev ของชีตนี้" (Rev แรกเลือกเลขเริ่มได้) · ตั้งคอลัมน์ที่ใช้เรียกชื่อแถวในรายการเปลี่ยนแปลงได้ในหน้าต่างเดียวกัน
- **คอลัมน์เติมอัตโนมัติ**: ตั้งค่าคอลัมน์วันที่ → "เติมวันที่แก้ไขล่าสุดให้อัตโนมัติ" · คอลัมน์ข้อความ → "เติมชื่อผู้แก้ไขล่าสุดให้อัตโนมัติ"
- **วิดเจ็ตแดชบอร์ด** (กลุ่ม "รายละเอียด"): *ค้นหารายละเอียด* (เลือกคอลัมน์ที่ค้น / หัวข้อ / รายละเอียด / รูป) และ *Rev ล่าสุด*
- **แดชบอร์ดบนมือถือ** (จอกว้าง < 640px, โหมดดู): วิดเจ็ตเรียงลงมาทีละชิ้นแทนการย่อทั้งผืนผ้าใบ

## สิ่งที่การนำเข้าจาก Excel จัดการให้ (ใช้กับ REV.9 ใน repo ด้วย)

- แถวที่ไม่มี Sub Doc No. / Material / Short Code แต่มีข้อความ = Note ที่ต่อจากแถวด้านบน → ต่อท้าย Note ของแถวนั้น (ไม่สร้างแถวใหม่)
- Sub Doc No. เดียวกันหลายแถว (หลาย Short Code) → นำเข้าครบทุกแถว แดชบอร์ดรวมเป็นการ์ดเดียว
- วันที่ที่ Excel เขียนเป็นข้อความ (หลายวันในช่องเดียว) → ช่องวันที่ใช้วันล่าสุด ข้อความเดิมอยู่ในคอลัมน์ "วันที่ Update (ข้อความเดิมใน Excel)"
- รูปที่วางใน Excel → ผูกกับแถวที่มุมซ้ายบนของรูปอยู่ (ถ้าอยู่ในแถวต่อของ Note ก็ผูกกับแถวหลัก) · แถวที่เขียนถึงรูปแต่ไม่มีรูปในไฟล์ต้องใส่เพิ่มเอง
- **ไม่ได้นำเข้า**: ชีต `QH` (หน้าค้นหาของ Excel → แทนด้วยแดชบอร์ด), `Special`, `Sheet1`, `Sheet4`

## ทดสอบแล้ว / ยังไม่ได้ทดสอบ

- ทดสอบ (SQL Server 2022 ในเครื่องทดสอบ): นำเข้าไฟล์ REV.8 และ REV.9 จริงครบทุกแถว + รูป + Rev, รันซ้ำแล้วหยุด, แก้ Note → วันที่/ชื่อเปลี่ยนเอง, พิมพ์ลงคอลัมน์เติมอัตโนมัติถูกปฏิเสธ, ป้าย `+1` บนปุ่ม Rev, ออก Rev ใหม่แล้วรายการเปลี่ยนแปลงถูก (ค่าเดิม → ค่าใหม่), ค้นหาด้วย Sub Doc No. (หลายแถว) และ Short Code บนแดชบอร์ด PC และ iPhone (จำลอง), unit test การเทียบ Rev
- ข้อมูล REV.9 ใส่เองตอนเปิดระบบ (ฐานข้อมูลใหม่): มีโฟลเดอร์ Quality Highlight Report / Data / Formular / Master Template อยู่แล้ว → ใส่ใน Data เดิม ไม่สร้างซ้ำ · ไม่มีโฟลเดอร์ → สร้างให้ · ยังไม่มีผู้ใช้ → รอรอบหน้า · เปิดระบบครั้งที่ 2 → ไม่ทำซ้ำ (7 ms) · ลบไฟล์ถาวรแล้วเปิดใหม่ → ไม่กลับมา · ตรวจผ่าน API: 396 แถว, รูป 3 รูปเปิดได้, Rev.9 (ยังไม่มีการแก้ค้าง), แดชบอร์ด 3 วิดเจ็ต
- ยังไม่ได้ทดสอบ: บน server จริง (Windows + SQL Server ของบริษัท), มือถือเครื่องจริง, ชีตใหญ่หลายหมื่นแถวกับ Rev (เก็บสำเนาทั้งชีตต่อ Rev)
