# ข่าวสาร · ขอ Tag · Tag All · Root และหน้าจัดการสิทธิ์

## ข่าวสาร (เมนู ข่าวสาร, `/news`)

- โพสต์ = หัวข้อ + รายละเอียด (ลิงก์ https:// กดได้) + รูปไม่เกิน 10 รูป + ลิงก์ (ไม่บังคับ) + **Tag ของคนที่ควรเห็น** (อย่างน้อย 1 Tag)
- เห็นข่าว: คนที่มี Tag ของข่าว (Tag **All** = ทุกคน) · ผู้โพสต์ · Admin / Root เห็นทุกข่าว
- โพสต์ได้: User ขึ้นไป (Viewer อ่านอย่างเดียว) · ปักหมุด: Master ขึ้นไป · แก้/ลบ: ผู้โพสต์ หรือ Admin
- ตัวเลขที่เมนู = ข่าวใหม่ที่ยังไม่ได้อ่าน (`NewsReads.last_seen_at`) · ข่าวที่ส่งถึง Tag ที่ไม่ใช่ All มีแจ้งเตือนที่กระดิ่งด้วย
- ตาราง: `NewsPosts`, `NewsPostTags`, `NewsReads` (`database/24_news.sql`) · API `server/src/modules/news` · หน้าเว็บ `client/src/modules/news`

## Tag All และการขอ Tag (คำขออนุมัติ → คำขอ Tag)

- **All** เป็น Tag ของระบบ (`Tags.is_system = 1`): ทุกบัญชีมีโดยไม่ต้องมีแถวใน `UserTags` — อ่านสมาชิกผ่าน view **`UserTagsAll`**
  (ใช้ใน `shared/permissions.ts`, `services/lookup.ts`, `routes/access.ts`, ข่าวสาร) · เปลี่ยนชื่อ / ลบ / ใส่สมาชิกไม่ได้ (เปลี่ยนสี / คำอธิบายได้)
- แชร์ไฟล์ / โฟลเดอร์ / ข่าวให้ **All** = ทุกคน
- **Master และ Admin** สร้าง / แก้ไข Tag และกำหนดสมาชิกได้ (แท็บ จัดการ Tag) · ลบ Tag ได้เฉพาะ Admin
- คนอื่น **ขอ Tag** ได้: เลือก Tag + เลือกว่าจะส่งถึง Admin / Master คนไหน → คนนั้นได้แจ้งเตือนและตัวเลขที่เมนู Tag →
  อนุมัติ (ใส่ Tag ให้ทันที) / ไม่อนุมัติ (ใส่เหตุผล) · Admin เลือก “ทั้งหมด (Admin)” เพื่อพิจารณาคำขอที่ส่งถึงคนอื่นแทนได้
- ตาราง `TagRequests` (`database/23_tag_all_requests.sql`) · API `server/src/modules/tags/requests.ts` · หน้าเว็บ `client/src/modules/tags`

## Root และหน้าจัดการสิทธิ์ (`/permissions`)

- บทบาท **root** (`Roles.role_id = 4`) ทำได้ทุกอย่างเหมือน Admin + หน้า **จัดการสิทธิ์** · `requireRole(...)` ให้ root ผ่านทุกครั้ง, `isAdminRole()` = admin หรือ root
- Admin แก้ไข / ปิด / รีเซ็ตรหัสผ่านบัญชี Root ไม่ได้ และให้บทบาท Root ได้เฉพาะ Root · ขอสร้างบัญชีขอ Root ไม่ได้
- **บัญชี root** สร้างเองตอน server เปิดครั้งแรกด้วยเวอร์ชันนี้ (`server/src/scripts/rootAccount.ts`) เมื่อยังไม่เคยมีใครเป็น root:
  ชื่อผู้ใช้ `root` รหัสผ่าน `Root@` + วันที่วันนั้นตามเวลาไทย `ddmmyyyy` (ค.ศ.) เช่น 11 พ.ย. 2026 → `Root@11112026`
  (log ของ server บอกวันที่ที่ใช้ ไม่บอกรหัสผ่าน) — **เข้าแล้วเปลี่ยนรหัสผ่านทันที** · ไม่มีรหัสผ่านอยู่ใน repo
- หน้า **จัดการสิทธิ์**: ตาราง หน้า × บทบาท (Viewer / User / Master / Admin; Root เห็นทุกหน้าเสมอ) + แถว **ผู้ช่วย AI** (ปุ่ม AI บนแถบด้านบน)
  - รายการหน้าและค่าเริ่มต้นอยู่ที่ `server/src/modules/pageAccess/registry.ts` (key ตรงกับ `client/src/lib/pages.tsx`)
  - `floor` = บทบาทต่ำสุดที่ให้ได้ เพราะฝั่ง server ยังตรวจบทบาทนั้น (จัดการผู้ใช้ = Admin, อุปกรณ์ / ดึงข้อมูล = Master) · หน้าแรก / ตั้งค่า ทุกคนเห็นเสมอ
  - ค่าที่ Root บันทึกอยู่ใน `RolePageAccess` (`database/22_root_role_page_access.sql`) · หน้าที่ไม่มีแถว = ค่าเริ่มต้น (หน้าที่เพิ่มทีหลังจึงมีค่าเริ่มต้นเอง)
  - บันทึกแล้ว browser ทุกเครื่องได้ event `pages:changed` → เมนูเปลี่ยนทันที · server ตรวจด้วย `requirePage(key)` ที่ ข่าวสาร, Monitor, Search, AI
  - ซ่อนเมนูไม่ได้ลบสิทธิ์ไฟล์: ไฟล์ที่แชร์ยังเปิดจากลิงก์ได้
- ปุ่ม **AI**: ค่าเริ่มต้นเห็นเฉพาะ Admin และ Root (API `/ai/*` ใช้กฎเดียวกัน)

## อื่นๆ ในชุดนี้

- **อีเมลไม่บังคับ** (`database/25_optional_email.sql`): `Users.email` / `AccountRequests.email` เป็น NULL ได้ อีเมลที่ใส่ยังห้ามซ้ำ (filtered unique index)
- **ย้อนข้อมูลทั้งชีต**: ปุ่ม “ย้อนข้อมูล” กดได้เมื่อ เลือกเวลา → กด “ดูผลกระทบ” → พิมพ์เหตุผลอย่างน้อย 5 ตัวอักษร (หน้าต่างบอกว่ายังขาดกี่ตัว)
- **แดชบอร์ดบนมือถือ**: ขนาดตัวอักษรที่ตั้งไว้สำหรับจอใหญ่ถูกย่อเมื่อเปิดบนมือถือ (`phoneSized` ใน `components/dashboard/widgets.tsx`) ค่าที่บันทึกไม่เปลี่ยน

## คำขออนุมัติ (หน้าเดียว `/requests`)

- รวม 4 แท็บ: **อนุมัติเอกสาร** (PDF ที่รอลงนาม / ที่ส่ง / ที่เกี่ยวข้อง) · **คำขอสิทธิ์ไฟล์** · **คำขอสร้างบัญชี** (Admin / Root) · **คำขอ Tag** (Master ขึ้นไป)
- ตัวเลขที่เมนู = คำขอสิทธิ์ไฟล์ + คำขอสร้างบัญชี + คำขอ Tag ที่รอคุณ · ตัวเลขบนแท็บแยกตามประเภท
- ที่อยู่เดิม `/approvals`, `/access-requests`, `/users/requests` (ลิงก์ในแจ้งเตือนเก่า) พาไปแท็บที่ตรงกันเอง (`ToRequests` ใน `client/src/pages/RequestsHubPage.tsx`)
- key ของหน้าในจัดการสิทธิ์: `requests` (แทน `access-requests` และ `approvals`)

## หน้าจออื่นๆ

- **เมนูด้านซ้าย**: ปุ่มมุมซ้ายบน (จอคอม) เลือก แสดงเมนูเต็ม / แสดงเฉพาะไอคอน / ซ่อนเมนู — จำไว้ใน browser (`localStorage dsp.navMode`)
- **ซูมหน้าจอ**: ปุ่มแว่นขยายที่แถบบน 70%–150% (`dsp.uiZoom`, CSS `zoom` ที่ `<html>`) — ของแต่ละเครื่อง ไม่กระทบคนอื่น
- **ลบรูปในแถว**: ปุ่ม ✕ ที่มุมรูปแสดงตลอด (เดิมเห็นเฉพาะตอนเอาเมาส์ชี้ บนมือถือจึงไม่เห็น)
- **ใส่ Tag รายคน**: หน้าจัดการผู้ใช้ ปุ่ม **+ Tag** ใต้ชื่อแต่ละคน แตะ Tag เพื่อใส่ / เอาออก บันทึกทันที
- **พิมพ์ลงตารางแบบ Excel (จอคอม)**: คลิกช่องแล้วพิมพ์ทับได้เลย (Enter ลง · Tab ขวา · ลูกศร · Delete ล้าง · Ctrl+C/V · Ctrl+Z) ·
  แถว **\*** ล่างสุดคือแถวใหม่ พิมพ์ทีละช่อง ครบช่องจำเป็นแล้วบันทึกเป็นแถวใหม่ให้เอง (✓ บันทึกทันที · ✕ ล้าง) — ไม่มีในจอสัมผัส (ใช้ + เพิ่มแถว),
  ชีตรวม และชีตรายการย่อยของหัวเอกสาร (ต้องเพิ่มผ่านหน้าต่างรายการเพื่อให้ผูกกับใบ) · ปุ่มที่กดเร็ว (สแกนเนอร์) ก่อนช่องพิมพ์ขึ้นไม่หาย
- **หัวเอกสาร ↔ รายการ**: ชีตที่มีรายการย่อยแสดงคอลัมน์ “N รายการ” หน้าเลขแถว · ชีตรายการแสดงคอลัมน์ใบที่เป็นเจ้าของ (กดเพื่อไปที่ใบ)
  (`/sheets/:id/lines/counts | map | header-sheet | parents`) · ตาราง PDF แบบฟอร์มต่อแถวเลือก “เฉพาะรายการของแถวนี้” ได้
- **มือถือ**: ตัวอักษรและระยะห่างเล็กลง 1 ขั้น (`html { font-size: 14px }` ที่จอ < 640px; ช่องพิมพ์คง 16px กัน iPhone ซูม) · การ์ดไฟล์ไม่ล้นจอ
  (ทางของไฟล์แสดงเฉพาะโฟลเดอร์ของมัน ชื่อยาวขึ้น 2 บรรทัด ไม่มีภาพตัวอย่าง)
- **PDF**: สัญลักษณ์ ✓ ✗ ☐ ★ … พิมพ์ด้วยฟอนต์สัญลักษณ์ (`public/fonts/DejaVuSans-Symbols.ttf` ~7 KB, ใบอนุญาต `LICENSE-DejaVu.txt`) — เดิมขึ้นเป็นกล่องว่าง
- **หลังอัปเดตเวอร์ชัน**: หน้าเว็บที่เปิดค้างไว้จะโหลดใหม่เอง 1 ครั้งเมื่อเจอไฟล์ของเวอร์ชันเก่าที่ถูกลบไปแล้ว
  (เดิมขึ้น “Failed to fetch dynamically imported module …” ตอนสร้าง PDF ฯลฯ ต้องกด Ctrl+F5 เอง)

## ชื่อระบบ และหน้า Tag เดิม

- **ชื่อระบบ** (ค่าเริ่มต้น `Quality`): ตั้งค่า → แท็บ **ชื่อระบบ** (Admin / Root) — แสดงที่มุมบนของเมนูซ้าย หน้าเข้าสู่ระบบ แท็บ browser และชื่อใต้ไอคอนมือถือ
  - เก็บใน `SystemSettings` (key `app_name`) · `GET /api/app-info` (ไม่ต้อง login) · server สร้าง `/manifest.webmanifest` ด้วยชื่อนี้ (`server/src/modules/appInfo`)
  - ไอคอนที่ติดตั้งไว้แล้วบนมือถือจะใช้ชื่อเดิมจนกว่าจะลบแล้วเพิ่มใหม่
- **เมนู Tag ถูกเอาออกจาก left bar** — ทุกอย่างย้ายไปแล้ว:
  - Tag ของฉัน → ตั้งค่า → โปรไฟล์ (ปุ่ม ขอ Tag)
  - ขอ Tag / คำขอของฉัน / รอฉันอนุมัติ / จัดการ Tag (Master+) → คำขออนุมัติ → แท็บ **คำขอ Tag** (`?tab=tags&box=mine|review|manage`)
  - `/tags` เดิมพาไปที่แท็บนี้เอง

## ประเภทเอกสารและ Rev

ตั้งต่อ**ไฟล์** (`Files.doc_type`, migration `26_doc_types.sql`) — เลือกตอนสร้างไฟล์ (บังคับในหน้าสร้างไฟล์) เปลี่ยนได้ที่ ⋯ → ประเภทเอกสาร (Master ขึ้นไปที่จัดการไฟล์)
หรือทั้งโฟลเดอร์ (⋯ ของโฟลเดอร์ → ตั้งประเภทเอกสารทั้งโฟลเดอร์, Admin) · การ์ดไฟล์มีป้ายประเภท · หน้าโฟลเดอร์กรองตามประเภทได้

| ประเภท | `doc_type` | Rev |
|---|---|---|
| Master Data (ข้อมูลหลัก) | `master_data` | Rev เก็บข้อมูลทุกแถว + รูปแบบ · แก้ข้อมูล/รูปแบบแล้วปุ่ม Rev มีตัวเลขเตือน (ไม่ต้องอนุมัติ) |
| แบบฟอร์มบันทึก | `record` | Rev (`kind = format`) เก็บเฉพาะ**รูปแบบ** · ข้อมูลที่ลงไม่ต้องออก Rev · แถวรู้ว่าลงด้วยแบบฟอร์ม Rev ไหนจาก `created_at` เทียบเวลาออก Rev |
| ทั่วไป | `NULL` | เหมือนเดิม (ออก Rev เองได้) — ไฟล์เดิมทั้งหมด |

- **รูปแบบ** (`SheetRevisions.format_json`, `server/src/modules/revisions/format.ts`) = คอลัมน์ (ชนิด ตัวเลือก เงื่อนไข/สูตร ค่าเริ่มต้น บังคับ คำอธิบาย ลำดับ)
  + ตั้งค่าชีต (Form layout, รายการย่อย, สแกน, Mix …) + แม่แบบ PDF ของไฟล์ที่ใช้ชีตนี้ · `format_diff_json` = สิ่งที่เปลี่ยนจาก Rev ก่อน
- ตั้งประเภท (หรือสร้างไฟล์ที่มีประเภท) แล้วชีตที่ยังไม่เคยมี Rev ได้ **Rev เริ่มต้น** อัตโนมัติ (`ensureBaseline`) · ชีตรวมข้อมูลไม่มี Rev
- seed `zz_doc_types_2026_11.sql` ตั้ง QH Master + Program MD = Master Data, ใบตรวจ F3QCPF06 = แบบฟอร์มบันทึก (server ออก Rev เริ่มต้นตอน start)
- แท็บชีต ⋯ → **Rev ของชีตนี้** (ทุกคนที่เปิดไฟล์ได้) · แถวในฟอร์มบอก “ลงด้วยแบบฟอร์ม Rev.N”
- แก้แม่แบบ PDF แล้วออก Rev: เมนูส่งออกมี “PDF — … (รูปแบบ Rev.N)” ใช้พิมพ์ใบเก่าด้วยหน้าตาเดิม (`GET /files/:id/pdf-revisions`)
