- ข้อมูลอยู่ใน repo: `database/seed/metal_detector_f3qcpf06.sql` — ใส่ครั้งเดียวต่อฐานข้อมูล ถ้ามีไฟล์ชื่อเดียวกันอยู่แล้วจะข้าม

## ทำครั้งเดียวหลังติดตั้ง (Admin)

1. **จัดการผู้ใช้ → Tag → MD → สมาชิก**: ใส่ชื่อพนักงานคุมเครื่อง / QC ที่ลงชื่อในใบตรวจ
   (ช่อง พนักงานคุมเครื่อง · Checked By (QC staff) · Checked By ของรายการ เลือกได้เฉพาะคนใน Tag MD)
2. ช่อง **Reviewed By (QC Section Manager)** เลือกได้จากผู้ใช้ทุกคน — ถ้าต้องการจำกัด: ตั้งค่าคอลัมน์ → รายชื่อผู้ใช้ในระบบ → เลือก Tag

## การใช้งาน (ดูภาพทีละขั้นที่เมนู คู่มือ → ใบตรวจ Metal Detector)

1. ชีต **หัวเอกสาร** → **+ เพิ่มแถว** → กรอกหัวกระดาษ → บันทึก (ได้เลขที่ใบตรวจ MD-YYMMDD-NNN อัตโนมัติ)
2. หน้าต่าง **รายการ** ของใบนั้นเปิดให้เอง → **+ เพิ่มรายการ** ทุกครั้งที่ตรวจ
   - วันที่ · กะ · หมายเลขเครื่อง เติมจากหัวเอกสาร
   - **ความถี่ (F)** เลือกได้หลายข้อในช่องเดียว (F0–F7)
   - **โปรแกรม / Sensitivity** แสดงเฉพาะโปรแกรมของเครื่องนั้น พร้อมค่าที่ควบคุม เช่น `038 Chunk PET-01 (Fe 3.5 / SUS 6.0)` หรือ `001 Chunk (ML1 9.0 / ML2 7.0 / ML3 9.0 / ML4 9.0)`
   - Fe · Non Fe · SUS · Large test piece · Result · รอบ A 1-2 · Object · รอบ B 1-3: **✓** ผลผ่าน · **x** ผลไม่ผ่าน · **-** ไม่พบปัญหา · **∙** ไม่ตรงกับรอบการตรวจ (ช่องผลการตรวจจับวัตถุดิบตั้งต้นเป็น -)
3. เปิดใบเดิม: ชีตหัวเอกสาร → กดรูปตาหน้าแถว → **รายการในแถว** · ค้นหาใบได้จากเมนู **Search**

## แก้ตาราง Program / ค่า Sensitivity

แก้ที่ชีตของโรงผลิต (Petfood / Petfood 2) — คอลัมน์ **โปรแกรม / Sensitivity** สร้างจากสูตรให้เอง (Program No. + Name + Fe/SUS หรือ ML1-4)
ชีตรวมและตัวเลือกในใบตรวจอัปเดตตามภายใน 1 นาที · เพิ่มเครื่องใหม่ = เพิ่มแถวพร้อมหมายเลขเครื่อง

## สำหรับนักพัฒนา

- โครงสร้างสร้างด้วย `server/scripts/buildMetalDetector.ts` (ผ่าน API บนฐานข้อมูลทดสอบ, ข้อมูลโปรแกรมจาก JSON ที่ไม่ได้เก็บใน repo)
  แล้ว `server/scripts/exportSeedSql.ts --file-id <โปรแกรม>,<ใบตรวจ> --folder "DAILY METAL DETECTOR SENSITIVITY TEST REPORT" --sub Data --rename-from "Metal Detector Report" --tags MD --grant-tag MD:write`
- ความสามารถทั่วไปที่ใช้: ตัวเลือกจากรายชื่อผู้ใช้ตาม Tag (`validation.lookup.users.tag`), รายการย่อยแบบกรอกฟอร์ม (`settings.lines.entry = 'form'`), ชีตรวม + ตัวเลือกที่กรองตามเครื่อง (lookup parent)

## ทดสอบแล้ว / ยังไม่ได้ทดสอบ

- ทดสอบ (SQL Server 2022): seed บนฐานใหม่ที่มีโฟลเดอร์ "Metal Detector Report" + Data/Formular/Master Template อยู่แล้ว → เปลี่ยนชื่อ ใส่ใน Data ไม่สร้างซ้ำ, ครั้งที่ 2 ข้าม · API 18 รายการ (177 โปรแกรม, ป้ายจากสูตรครบ, เครื่อง 27 รายการ, โปรแกรมกรองตามเครื่อง, ชื่อนอก Tag MD ถูกปฏิเสธ, โปรแกรมของเครื่องอื่นถูกปฏิเสธ, รูปแบบเวลา, เลขที่ใบตรวจ) · หน้าเว็บ: สร้างหัว → หน้าต่างรายการเปิดเอง → เพิ่มรายการ (เติมเครื่อง/วันที่) → โปรแกรมเฉพาะเครื่อง
