# InkCode — ระบบออกโค้ดนอกแผน (แทนไฟล์ Excel 2 ไฟล์)

## โครงสร้างที่สร้างให้ (โฟลเดอร์ `InkCode`)
| ไฟล์ | ชีต | หน้าที่ |
|---|---|---|
| InkCode - รหัสอ้างอิง | ปี · เดือน · วัน · ไลน์ · กะ · ปฏิทิน | ตาราง Ref เดิม (รหัสปี, รหัสเดือน A-M, รหัสวัน, รหัสไลน์, Julian ฯลฯ) แก้ได้ที่นี่ที่เดียว |
| InkCode - Master Database | ฐานข้อมูล (2,896 แถว) | 1 แถว = รหัสเอกสาร + Market พร้อม **แบบโค้ดแถว 1-4**, SAP, วัสดุ ฯลฯ |
| InkCode - ใบออกโค้ดนอกแผน | Worksheet | พนักงานกรอก วันที่ผลิต · ไลน์ · กะ · รหัสเอกสาร · Market → ระบบเติมลูกค้า/ชนิด/SAP และ **Code Format แถว 1-4** ให้เอง |

PDF "ใบออกโค้ดนอกแผน 4 ส่วน": เลือกแถวใน Worksheet → ส่งออก PDF → ได้ 4 สำเนา (คั่นเส้นประ) มีกริด 40 ช่อง × 4 บรรทัด และช่องลงชื่อ

## แนวคิด: แบบโค้ด (template) แทนสูตรเป็นสิบแบบ
ใน Excel แต่ละสินค้าใช้สูตรต่างกัน (BBE:, BEST BY, BC…BB, Julian ฯลฯ) DocHUB เก็บเป็น **แบบข้อความ** เช่น `{P} S{YC}{MC}{DC}S{LC}`
ฟังก์ชัน `FILL(แบบ, ตัวแปร)` แทนค่าให้ตามวันที่ผลิต/ไลน์ของแถว
ตัวแปร: `{P}` Short code · `{F}` รหัสเอกสาร · `{Y}` `{Y+3}` `{YY}` `{Y1}` ปี · `{D}` `{DD}` `{DD-1}` วัน · `{Mo}` `{MM}` เดือน · `{YC}` รหัสปี · `{MC}` รหัสเดือน · `{MON}` JAN · `{M2}` JA · `{DC}` รหัสวัน · `{LC}` `{LC2}` `{PF}` รหัสไลน์ · `{SC2-4}` รหัสกะ · `{K2…K10}` ปฏิทิน (`{K6L3}` 3 ตัวแรก, `{K6R1}` 1 ตัวท้าย, `{K3-1}` วันก่อนหน้า)
เพิ่มสินค้าใหม่ = เพิ่ม 1 แถวใน "ฐานข้อมูล" แล้วพิมพ์แบบโค้ดของมัน

```

```
สคริปต์เรียก API ปกติ (ตรวจสิทธิ์/บันทึก audit เหมือนใช้หน้าเว็บ) ไม่แตะ SQL ตรง และไม่เขียนทับ — ถ้ามีไฟล์ชื่อเดียวกันในโฟลเดอร์จะข้าม
ข้อมูลอยู่ใน `scripts/inkcode/data/*.json` สร้างจาก Excel ด้วย `python3 scripts/inkcode/extract.py "<Master_Database.xlsx>" [รหัสผ่านไฟล์]` (ต้อง `pip install msoffcrypto-tool openpyxl`)

## สิ่งที่ต้องตรวจก่อนใช้จริง
1. **790 จาก 2,896 แถว (27%) แปลงสูตร Code Format เป็นแบบโค้ดอัตโนมัติไม่ได้** — ช่อง "แบบโค้ดแถว" ของแถวนั้นว่าง สูตรเดิมอยู่ในคอลัมน์ "สูตรเดิมที่ต้องตรวจ" (กรองไม่ว่าง) ส่วนใหญ่อ้างชีต `up date Ref2026`, วันหมดอายุที่คำนวณซ้อนจากปฏิทิน หรือลิงก์ไปไฟล์ Master รุ่นเก่า ต้องให้คนรู้กฎพิมพ์แบบโค้ดเอง
2. ข้อความที่พิมพ์ไว้ตรง ๆ ใน Excel (เช่น `COMPLEMENTARY CAT FOOD NW:55g`) ถูกเก็บเป็นแบบโค้ดที่ไม่มีตัวแปร
3. **คีย์ซ้ำ 114 คู่** (รหัสเอกสาร + Market) — LOOKUP ใช้แถวแรก ตรวจว่าแถวไหนถูก
4. สูตรเดิมใช้ `DAY(วันที่-1)` คู่กับ `MONTH(วันที่)` (วันที่ 1 ของเดือนจะได้วันสุดท้ายของเดือนก่อนคู่กับเดือนปัจจุบัน) DocHUB ทำตามเดิม ถ้าเป็นบั๊ก ต้องแก้แบบโค้ดเอง
5. ไม่ได้ย้ายชีต Can/Pouch/Cup ของไฟล์ Pet Food (แบบฟอร์มพิมพ์ที่พิมพ์ตัวอักษรไว้ด้วยมือรายไลน์) และชีต `up date Ref2026`, `MARS-STD`, `PFC80`, `%ทวนสอบ`
6. ลิงก์ภายนอกของ Excel ไม่มีอีกต่อไป — ข้อมูลทั้งหมดอยู่ใน DocHUB

## ทดสอบแล้ว / ยังไม่ได้ทดสอบ
- ทดสอบ: สูตรทั้งหมดคอมไพล์และคำนวณถูกเทียบกับกฎ Excel ด้วยตาราง Ref จริง (รหัสปี/เดือน/วัน/ไลน์, BBE, MID), สคริปต์สร้างข้อมูลผ่าน API จำลองที่ตรวจโครงสร้างคำขอด้วย schema จริง, บล็อกกริด 40 ช่อง
- ยังไม่ได้ทดสอบ: การรันบน SQL Server จริง, เทียบกับ Excel ทีละแถวด้วยวันที่จริง, หน้าตา PDF ในเบราว์เซอร์ (ขนาดตัวอักษร/ช่องกริด)

## เพิ่ม/แก้ข้อมูล (ทุกอย่างอยู่ในไฟล์บนเว็บ ไม่มีอะไรซ่อนหลังบ้าน)
| อยากทำ | ทำที่ไหน |
|---|---|
| สินค้า/รหัสเอกสารใหม่ | `InkCode - Master Database` › ฐานข้อมูล › เพิ่มแถว (รหัสเอกสาร, Market, ลูกค้า, SAP, Short Product Code, **แบบโค้ดแถว 1–4**) |
| ไลน์ใหม่ / รหัสปีใหม่ / กะ | `InkCode - รหัสอ้างอิง` › ชีตไลน์ / ปี / กะ |
| ออกโค้ดประจำวัน | `InkCode - ใบออกโค้ดนอกแผน` › Worksheet › เพิ่มแถว (เลือกไลน์ กะ รหัสเอกสาร Market จากรายการ) |
| ดูว่าแบบโค้ดแต่ละตัวให้ผลอะไร | ฐานข้อมูล › คอลัมน์ "ตัวอย่างโค้ดแถว 1–4" (คำนวณจากวันที่/ไลน์ในชีต "ตัวอย่าง" ของไฟล์รหัสอ้างอิง — แก้วันที่ตรงนั้นได้) |
| ดูว่า `{P}` `{YC}` ฯลฯ มาจากไหน | ฐานข้อมูล › ชีต "คู่มือตัวแปร" (ไฟล์/ชีต/คอลัมน์ต้นทางของทุกตัวแปร) และคำอธิบายที่หัวคอลัมน์ "แบบโค้ดแถว" |

ถ้าไลน์ที่พิมพ์ไม่ตรงกับชื่อในชีตไลน์ (เช่นพิมพ์ `line A` แต่ในตารางคือ `Auto A`) รหัสไลน์ `{LC}` จะว่าง — Worksheet จึงใช้ช่องเลือกจากรายการแทนการพิมพ์เอง

## ถ้าสร้างชุดแรกไปแล้ว (เวอร์ชันก่อนมี dropdown / ตัวอย่างโค้ด / คู่มือ)
สคริปต์ไม่เขียนทับของเดิม: ลบ 3 ไฟล์ใน InkCode (ไปถังขยะ) แล้วรัน `seedInkCode.ts` ใหม่ ข้อมูลที่เคยกรองใน Worksheet จะหาย (ถ้ามีข้อมูลจริงแล้ว ให้ส่งออกเป็น Excel เก็บไว้ก่อน)

## นำเข้าแผนผลิตประจำวัน (Excel) → Worksheet
ใน Worksheet มีปุ่ม **"นำเข้าแผนผลิต (Excel)"** — ลากไฟล์แผนผลิต (เช่น `แผนผลิต … 03-10-2026.xlsx`) มาวาง หรือคลิกเลือกไฟล์ ระบบ:
1. หาชีตที่มีหัวคอลัมน์ Time · Product · Line · Country · Doc.No และวันที่จากข้อความ "ประจำวันที่ …"
2. รวมแถวซ้ำของสินค้าเดียวกัน (แผนเขียน 3–4 แถวต่อสินค้า) เหลือ 1 รายการต่อ (เวลา, ไลน์, Doc.No, ประเทศ)
3. แปลงไลน์ (`Cup`+`1` → `Cup 1`, `Can`+`U` → `Can U`, `Auto B+C` → `Auto B` ฯลฯ), คำนวณกะจากเวลาเริ่ม (06:00–18:59 = DS, นอกนั้น NS), ตรวจว่ารหัสเอกสาร + ประเทศมีในฐานข้อมูล
4. แสดงตัวอย่าง ให้เลือกจับคู่ไลน์ที่ไม่รู้จักก่อนนำเข้า แล้วเพิ่มแถวใน Worksheet — โค้ด 4 แถว ลูกค้า ชนิด SAP Mat. Packaging ฯลฯ คำนวณเอง
- ไม่เพิ่มซ้ำ: แถวที่วันที่ ไลน์ เอกสาร ประเทศ (และเวลา) ตรงกันอยู่แล้วจะข้าม
- ค่าเริ่มต้นนำเข้าเฉพาะที่พบในฐานข้อมูล (ไม่งั้นช่อง Market ที่เป็นรายการเลือกจะไม่รับค่าที่ไม่มีในฐานข้อมูล)
- Doc.No ของสินค้า = Doc.No ที่พบมากที่สุดในแถวของสินค้านั้น (แถววัตถุดิบอาจมี Doc.No อื่น เช่น `MRDPF184/26` แทรกอยู่ จะไม่ถูกนำมาใช้)
- ทดสอบกับแผนวันที่ 03/10/2026: พบ 65 รายการ (จาก 272 แถว) ตรงฐานข้อมูลครบ 65; ราว 10 รายการมีชื่อไลน์ที่ไม่ตรงตารางรหัส (เช่น `PF2 ชั้นบน`) ต้องจับคู่ในหน้าตัวอย่าง
- ยังไม่ได้ทดสอบกับ SQL Server จริง; ยังไม่มีการลากไฟล์ไปวางบนรายการโฟลเดอร์โดยตรง (ใช้ปุ่มในหน้า Worksheet)

## ฟอร์ม PDF "ใบแจ้งการเปลี่ยนแปลงการผลิต (นอกแผน)"
ออกแบบตามต้นฉบับ: ตารางเดียวต่อ 1 ใบ — ไลน์ · ลำดับ · ลูกค้า · ชนิด · ตำแหน่ง 1–40 (4 บรรทัดโค้ด) · Mat. Packaging · Code (PO / New code / Code Sap) · รหัสเอกสารสูตรการผลิต · รหัสเอกสารระบบ Code/Rev. · QR Code · ช่องลงชื่อ ผู้จัดทำ/ผู้ตรวจสอบ ×2
กระดาษ A3 แนวนอน พิมพ์ 4 ฉบับต่อหน้า (คั่นเส้นประ) แก้เลย์เอาต์ได้ที่ "ออกแบบรูปแบบ PDF" (บล็อก "ตารางโค้ด") — ช่อง QR Code เว้นว่างตามต้นฉบับ (ยังไม่สร้าง QR ให้)
เลข "ลำดับ" = เลขแถวใน Worksheet; "New code" = คอลัมน์ Code ฝน; วันที่/กะ = วันที่ผลิต/กะของแถว; เลขที่ฟอร์ม `F3PFPF39-0-04/10/21` เป็นข้อความตายตัวในเทมเพลต

### ซ่อนช่องตำแหน่งที่ไม่ใช้ และ QR Code (บล็อก "ตารางโค้ด")
- **ซ่อนช่องตำแหน่ง**: แต่ละใบแสดงเฉพาะช่องตั้งแต่ 1 ถึงตัวอักษรสุดท้ายของบรรทัดที่ยาวที่สุด (อย่างน้อย 12 ช่อง ตั้งได้) ช่องที่ซ่อนจะคืนความกว้างให้คอลัมน์อื่น ตารางยังเต็มความกว้างหน้ากระดาษ
- **QR Code อัตโนมัติ** ใช้วิธีเดียวกับเครื่องมือ QR Code Tool ของโรงงาน: เอา 4 บรรทัดโค้ด บรรทัดละ N ตัวอักษร (เติมช่องว่างให้ครบ) ต่อกัน แล้วตัดช่องว่างท้ายออก → QR; **Can = 23 ตัวอักษร/แถว, อื่นๆ (Pouch/Cup ฯลฯ) = 40** ตัดสินจากคอลัมน์ PKG ของสินค้าในฐานข้อมูล (Worksheet ดึงมาให้เอง)
- ตรวจแล้ว: เรนเดอร์ PDF แล้วถอดรหัส QR ด้วยตัวถอดรหัสอิสระ (jsQR) ได้ข้อความตรงกับที่ควรเป็นทั้งแบบ 40 และ 23 ตัวอักษร/แถว (ยังไม่ได้ทดสอบสแกนด้วยมือถือจริง/เครื่องสแกนของโรงงาน)
- ขนาด QR ≈ 20 มม. (สูงเท่า 4 บรรทัด) ถ้าสแกนยากให้เพิ่มความสูงช่อง (`cellHeightMm`) หรือความกว้างคอลัมน์ QR ในหน้าออกแบบ
- ตั้งค่าได้ในหน้าออกแบบ PDF › บล็อกตารางโค้ด › QR Code
- ขนาด QR: ค่าเริ่มต้น = ใหญ่เท่าที่ช่องรับได้ (เว้นขอบขาว 0.8 มม.) หรือกำหนดเองในหน้าออกแบบ › บล็อกตารางโค้ด › QR Code › "ขนาด QR (มม.)" ถ้าตั้งใหญ่กว่าช่อง ระบบเพิ่มความสูงแถวโค้ดและความกว้างคอลัมน์ให้พอดี (ใบจะสูงขึ้น 4 ฉบับอาจไม่พอดี 1 หน้า A3)
- แก้บั๊ก: QR เล็กกว่าที่ตั้ง/หายเมื่อตั้งขนาดเล็ก (10 มม.) เพราะ pdfmake ปัดขนาดโมดูลลงเป็นจำนวนเต็มจุด — ตอนนี้วาด QR เองให้ได้ขนาดตรงที่ตั้ง; คอลัมน์ QR ไม่ถูกขยายตามช่องตำแหน่งที่ซ่อน (ไม่เกิดขอบขาวข้างๆ) — ขอบขาวรอบ QR แนะนำ 1.5–3 มม. (ขอบขาว 0 สแกนยากด้วยมือถือ)
- พิมพ์หลายแถวต่อ 1 หน้า: ในหน้าออกแบบ PDF (โหมด "แบบฟอร์มต่อแถว") ตั้ง "จำนวนฟอร์ม (แถว) ต่อ 1 หน้า" เช่น 4 → วาง 4 แถวที่เลือกต่อหน้า A3 คั่นเส้นประ (ปิดการพิมพ์ซ้ำหลายสำเนาไว้) — อย่าเปลี่ยนเป็นโหมด "รายงานตาราง" เพราะบล็อกตารางโค้ดใช้ได้เฉพาะโหมดฟอร์มต่อแถว (ข้อมูลจะไม่ขึ้น)

* ชีตเป็นสำเนาโครงของ Worksheet (คอลัมน์ สูตร dropdown เหมือนกัน) — โค้ด 40 ตัว 4 แถวคำนวณเองจากสูตร
* พื้นที่ของไลน์: ชื่อไลน์มี Cup → Cup · Can → Can · Pouch/Spout/Auto → Pouch · นอกนั้น → อื่นๆ (แก้ที่ `areaOf` ใน `model.ts`)
* โรงงาน/พื้นที่: ดูจากคอลัมน์ **`โรงงาน`** และ **`พื้นที่`** ของไลน์ในตาราง ไลน์ (กติกาโรงงานอยู่ใน `LINE_SPEC` ใน `model.ts`; คอลัมน์ `Plant` เดิมใช้ต่อได้ถ้า `โรงงาน` ว่าง) → ไม่มีให้ดูข้อความ "PF2" ในชื่อไลน์ของแผน → ไม่ได้อีกให้เลือกเองในหน้านำเข้า

```cmd
cd /d I:\DATAHUB\server

```

### นำเข้าแผนผลิตอัตโนมัติ

0. **วางใน DocHUB (แนะนำ)**: เปิด `InkCode - ใบออกโค้ด › แผนผลิต › <ปี> › <เดือน>` — มีกล่อง “วางไฟล์แผนผลิต” ลากไฟล์ .xlsx มาวาง (หรือคลิกเลือก) ระบบนำเข้าทันที แสดงผลต่อโรงงาน/ชีต และทิ้งไฟล์บันทึกผลทุกแถวไว้ในโฟลเดอร์เดือนนั้น (ไลน์ที่ไม่ทราบโรงงาน/ไม่พบในฐานข้อมูลถูกข้ามและระบุในไฟล์บันทึก — ใช้ข้อ 1 เพื่อเลือกเอง)
1. **หน้าเว็บ** เมนู “นำเข้าแผนผลิต” (Master/Admin): วางไฟล์ → เห็นตารางว่าแถวไหนไปโรงงาน/ไฟล์/ชีตไหน → กดนำเข้า (แถวที่มีอยู่แล้วไม่เพิ่มซ้ำ)
2. **(ไม่บังคับ) โฟลเดอร์บนดิสก์เซิร์ฟเวอร์** `<INKCODE_PLAN_DIR>\<ปี>\<เดือน>\แผน.xlsx` — เซิร์ฟเวอร์ตรวจทุก 1 นาที แล้วนำเข้าเอง ไฟล์ที่เสร็จย้ายไป `เสร็จแล้ว\` (พร้อมรายงาน .txt) ที่ผิดพลาดย้ายไป `ผิดพลาด\`
   ตั้งใน `server/.env`:
   ```
   INKCODE_PLAN_DIR=D:\InkCodePlans
   INKCODE_PLAN_USER=<ชื่อผู้ใช้ master/admin ที่จะเป็นผู้สร้างไฟล์/แถว>
   ```
   แล้ว `pm2 reload datahub-server` — ถ้ามี 2 เซิร์ฟเวอร์ ให้ใช้พาธเครือข่าย (UNC) ที่ทั้งสองเครื่องเข้าถึงได้
3. วันที่ผลิตมาจาก “ประจำวันที่ …” ในแผน (ไม่ใช่ชื่อไฟล์/โฟลเดอร์) — ไลน์ที่ไม่รู้จักหรือไม่ทราบโรงงานในโหมดโฟลเดอร์จะถูกข้าม (ดูรายงาน) ให้ใช้หน้าเว็บเลือกเอง

### รูปแบบ PDF กลาง (แก้ที่เดียว ทุกไฟล์เปลี่ยนตาม)

* สคริปต์ตั้งให้ทุกไฟล์ในโฟลเดอร์ `InkCode - ใบออกโค้ด` ใช้รูปแบบ PDF ของ `InkCode - ใบออกโค้ดนอกแผน`
* แก้รูปแบบที่ไฟล์นั้นครั้งเดียว (หน้า “ออกแบบรูปแบบ PDF”) ทุกไฟล์รายเดือนเปลี่ยนตามทันที — ไม่ต้องคัดลอก
* รูปแบบต้องเปิด “ใช้กับชีตที่กำลังพิมพ์” (รูปแบบที่สร้างโดยสคริปต์เปิดไว้แล้ว) เพื่อให้พิมพ์จากชีตวันไหนก็ได้
* ตั้งเองได้: หน้าออกแบบ PDF › “ใช้เป็นรูปแบบกลาง” › เลือกโฟลเดอร์ · ไฟล์ที่ใช้รูปแบบกลางจะแก้รูปแบบของตัวเองไม่ได้ (กด “เลิกใช้รูปแบบกลาง” เพื่อได้สำเนาไปแก้เอง)
* ต้องรัน `database/17_pdf_master.sql` ก่อน (เพิ่มคอลัมน์ `Files.pdf_master_id`)

### แยกลูกค้า + ลายเซ็นต่อลูกค้า

รูปแบบ “ใบออกโค้ดนอกแผน แยกตามลูกค้า (ลายเซ็นต่อลูกค้า)”: จัดกลุ่มตามคอลัมน์ Market — ลูกค้าแต่ละรายขึ้นหน้าใหม่ มีหัวเอกสารครั้งเดียว ใบแจ้งของลูกค้านั้นเรียงต่อกัน แล้วปิดด้วยลายเซ็นชุดเดียว
ตั้งเองได้ในหน้าออกแบบ PDF: “จัดกลุ่มตามคอลัมน์” + ต่อบล็อก “พิมพ์บล็อกนี้ ครั้งเดียวต้นกลุ่ม / ท้ายกลุ่ม”

### นำเข้าแผนในชีตรายวัน

* ชีตใน `…/<PF1|PF2>/<ปี>/<YYYY-MM …>/<DD>`: ระบบรู้ว่าชีตคือวันไหน — ถ้าวันที่ในแผนไม่ตรงจะเตือนและไม่ให้นำเข้า (ติ๊กยืนยันได้)
* รู้ว่าเป็นโรงงานไหน จากชื่อโฟลเดอร์ PF1/PF2 — นำเข้าเฉพาะไลน์ที่ `Plant` ในตาราง ไลน์ ตรงกัน (ปิดได้)
* เลขวันที่จาก Excel อ่านถูกวันแล้ว (เดิมเซิร์ฟเวอร์เขตเวลา UTC+7 อ่านเพี้ยนไป −1 วัน)

### เลข 0 ในกริดโค้ด

เลข `0` พิมพ์เป็น Ø มีขีดทแยง และพื้นเทาอ่อน เพื่อแยกจากตัวอักษร `O`
